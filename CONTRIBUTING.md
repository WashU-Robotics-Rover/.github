# Contributing

WashU Robotics Rover uses GitHub teams for access.

- Join `all-devs` when you join the rover team.
- Join `software`, `electrical`, `mechanical`, or `science` for your subteam.
- Subteam leads are added to `leadership` by the rover captain.

Every organization member can read repositories. The software team can change the software repositories. Leadership maintains them.

## Software changes

Work in the private `grizzly` repository.

1. Branch from `main`.
2. Open a pull request into `main`.
3. Request review from the software team.
4. Squash-merge after approval.

Do not push new feature work to `grizzly-mvp-26` or `grizzly-25-26`.

Do not commit secrets, credentials, tokens, or competition-site keys. If a secret is committed, tell leadership immediately and rotate it.

## Reviews

The software team owns reviews in `grizzly` until subsystem owners are assigned. One approval is the expected bar before merge. Leadership can merge when a review is blocked and the change is needed for a test or competition deadline.
